How it is written

Written as files, checked as a whole.

A cloud and a timed machine are written the way one machine is: in plain text files, in one language, checked before anything boots by the part of harb called the court. Nothing manages either afterwards. This page says what you write, what the court refuses, and what is left out on purpose.

What you write

Three kinds of file, and four lines on a program.

A machine file

Says what one machine is and what each program on it may use: the network, which disks, which user, how much memory. harb check reads it against the language's rules and refuses what breaks one, naming the line.

A fleet file

Names the machines of one estate, each with the public key it is enrolled by, the networks it sits on (the fleet file calls a network a link), and which machine is the way between two of them. It is judged as a whole, because some mistakes belong to no single machine.

A pack

A solution's server programs on their own, written apart from any machine: what each one needs to run. harb place puts a pack on a machine, and the machine's own checks judge the result as one machine.

a program's time, in machines/qemu_deadline.machine
-- on a program: the four together, or none (and CORES 2 on the machine)
DEFINE SERVICE control AS (
  RUN ["/harb", "reserved", "--stay", "/run/control.ready"],
  RESTART always, READY "/run/control.ready",
  PERIOD 1000,
  DEADLINE 500,
  RUNTIME 200,
  CORE 1,
  NEEDS [process]
) RATIONALE "..."

PERIOD is how often the work comes round, in microseconds; DEADLINE by when, inside each period, it must be done; RUNTIME how much of the processor the kernel reserves for it every period; CORE which core, never core 0, the machine's own; CORES, on the machine, how many it has. From these the machine derives the kernel, the core set apart, and the reservation handed to the program before its first instruction. The program may not ask the kernel for any of this: the call that would is refused to every program. A program that runs past its runtime is told so by the kernel, with a signal it must ask to hear: it handles the word, or is ended by it.

What the court refuses

Before anything boots, with the line named.

For a set of machines, the states it must never be in: two machines that each serve the same network, two that claim one address, a box that is the way between two networks that nobody declared joined, a machine on a joined network with a way there and no way back. Each is a refusal the court makes while the cloud is still text.

For a program's time: one of the four numbers without the others; a runtime longer than its deadline, or a deadline past the period; a period the kernel would not hold (its own bounds are 100 microseconds to 4194304); core 0, or a core the machine does not have; a ceiling on the processor beside a reservation of it; and the reservations of one core asking more than 90 per cent of it — the kernel admits 95 and keeps 5 of those for the ordinary programs' own scheduler, which the court learned when two programs asking 95 together were refused the second at boot. The refusal names the line that crossed the bound, not the first program on the core.

Left out on purpose

What a cloud and a real-time system usually have, and these do not.

  • No discovery, no autoscaling. The fleet file is the list of who is in the set; a program that discovered or added machines would be a second source of truth about it. Capacity is one line and one image.
  • No automatic enrolment. A machine joins when a person copies its public key into the fleet file; an automatic one would trust whatever answered on the wire.
  • No hypervisor in the product. More programs on one machine is density, more machines is isolation between owners, and a provider's virtual machine is simply the hardware.
  • No priorities. A priority is a claim nobody checks; a reservation is refused when it does not fit, and the calls that would set a priority are refused to every program.
  • No real-time interface. No scheduler to call, no thread to pin: a reserved program is an ordinary program on a core set apart, and whatever it starts runs without a reservation.
  • No declared timing. The kernel's model is derived from the fact that a program reserves time, and read back at every boot; a machine that reserves nothing gets the calm kernel it always had.

What you keep

Your declaration, your evidence, your time.

The same files describe a cloud on hardware you own and, once the fourth step is built, on a machine you rent; what changes is who holds the keys, because each machine makes its own the first time it boots. On a machine somebody else owns you keep the declaration, which is the file, and the evidence, because every record is signed and anyone holding the fleet's public keys can check it. A program keeps its reservation for as long as it runs, given before it becomes the user it runs as; what it does not keep is a promise about the number, which is the witness's to measure.

The honest promise is your declaration and your evidence, and time the kernel holds with a number you can read — never "your cloud", never "real time".
