Built from first principles, on proven Linux, for critical work that must keep running — and stay its owner's — when everything else stops.

declare · judge · plan · boot · narrate one file, one job no account · no store · no drift
hello.machine — you write this
DEFINE MACHINE hello AS (
  ARCH x86_64,
  KERNEL linux
) RATIONALE "the smallest machine that boots"

DEFINE SERVICE greet AS (
  RUN ["/app/greet"]
) RATIONALE "say hello, then exit"

A whole machine, in nine lines. Each part must say why it is there.

your laptop — check it, then boot it
$ harb check hello.machine
hello -- judged, no refusal

$ harb boot hello.machine
boot: harb init -- machine hello -- pid 1
boot: mount /proc /sys /dev -- done
boot: start greet -- /app/greet
greet: hello from a declared machine
boot: greet exited 0
boot: judge -- the boot matches the file

check reads the file and rules on it; boot runs it in an emulator — no hardware needed.

Who it is for

The people who design the whole solution — software and hardware.

If you build both the software and the device it runs on, the operating system has always been the one layer you were handed instead of one you designed. You inherited its assumptions, its update policy, its ecosystem — and then spent your time working around them.

Harobanda gives that layer back. The operating system becomes part of your solution's model, shaped by the constraints of your domain, not by a general-purpose system built for everyone and no one. A machine you declare is a machine you designed: it does your job, keeps your guarantees, and carries nothing you did not put there.

For a full-stack designer, the machine is the missing floor — the last layer that was never yours to shape.
