Where it stands

Five steps built of twelve, in an emulator.

A cloud and a timed machine are each built in the order their parts depend on one another. This page says where each step stands and what judges it. Everything built has run only in an emulator, none of it for a customer, and nothing has moved a motor.

The cloud, six steps

In the order each one needs the one before.

1 · A serverA solution's server, placed on a machine. A pack, the server programs written apart from any machine, is put on one, which runs the server as a confined program under a user of its own. Judged by a boot compared line for line with its kept transcript, and by the same machine with no disk behind the server's directory, which does not start it.built · emulated
2 · Two linksA box that is the way between two networks. The fleet file says which box and which networks, and a till on one network reaches a server on the other through it. Judged by three machines on two networks, by the same box without its one line, and by a device nobody declared, which is given nothing.built · emulated
3a · TimeA date a record can lean on. A fleet's one time authority signs that an entry of a record existed no later than a time it read from its clock; a record with no such statement says it is ordered and undated. Judged by two machines on one wire, and by breaking each rule to see that a check catches it.built · emulated
3b · A frontA program at the edge that ends TLS, with its key on a disk the machine declares. Until it exists, a server is reached over plain HTTP from the networks of its own cloud, and from nowhere else.not built
4 · ProviderThe same file, booted on a machine somebody else owns, with the same two slots and the same trial as a board has. Today the emulator is handed the kernel directly.not built
5 · RolloutAn update that goes through the set a wave at a time, the next wave starting only when every machine of the current one has kept its own trial. Today each machine judges its own trial, and nothing judges the set.not built
6 · WitnessA filter behind the routes, and a witness that collects every machine's signed record and checks it with the fleet's public keys, holding no secret, so that an auditor reads one page. Today a route is a way both ways, and one record is checked at a time.not built

The timed machine, six steps

From the kernel to the robot as a set.

1 · A timed kernelA kernel that can meet a deadline, built to be interrupted almost anywhere, with timers that resolve to the nanosecond, derived from the fact that a program reserves time. Judged by the machine reading back, at every boot, what kernel it got.built · emulated
2 · A reservationTime the kernel holds for a program: a period, a deadline, a runtime and a core, on a core set apart, handed to the program before its first instruction. Judged by a boot of two reserved programs and one with none, by the court's cases, and by four things put wrong on purpose, each refused on the line that names it.built · emulated
3 · A measurementHow late the program actually woke. A witness runs the declared period on an absolute timer and says the median, the 99th, the worst and the misses. The kept transcript holds the line's shape and no number, because an emulator's time is its laptop's.built · emulated
4 · A safe stateWhat happens when the brain goes quiet. A motor needs an answer in milliseconds and the machine's own loop runs four times a second, so the safe state belongs to the body: a declared heartbeat from brain to body, and the body's declared act when the beat stops. On the machine's side, the court will refuse a health window shorter than the machine can keep.not built
5 · The edge scheduleHard real time, where it is possible. The edge profile, where a program is compiled onto a microcontroller, gains a declared schedule — how often each step runs, in what order, and the worst time its author promises for one — checked frame by frame before any chip is flashed. That is the MicroRing substrate's to build.not built
6 · The robot as a setA brain, a body and the wire between them, in a fleet file with two kinds of member, judged for the states no single machine can be in. A body does not move while its brain is trying an update.not built

Said plainly

What the boots do not show.

  • No board. Every boot on these pages ran in an emulator: the time statements read a clock the emulator hands the authority, and every latency is the laptop's. The first number that counts is a Raspberry Pi's, which waits on hardware.
  • No customer's server, and nothing to rent. RingServ stands in for a customer's server, and none is placed.
  • A route is a way both ways, and forwarding filters nothing. No packet filter exists, and two networks are joined through one box, not a chain.
  • Time has one source and one bound. One authority per fleet, a clock it was declared to have, no time from the network, and "no later than", never "how long before".
  • Not a real-time operating system. No priorities, no scheduler to call, no thread to pin; one core per program, and what a program starts runs unreserved.
  • No kernel's word is taken on trust. Five numbers copied from the kernel's source were wrong when the kernel was asked, and each was caught by a line the machine prints to be read back.
  • The body is not here. The safe state, the edge schedule and the robot as a set need a microcontroller, a wire and the MicroRing substrate. Nothing has moved a motor.
