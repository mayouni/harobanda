Real time

A machine that gives a program its time.

A real-time system is built on Harobanda the way any solution is: it brings its control loop, and the machine brings the time and the proof. A program declares the time it needs, the kernel keeps it on a core set apart and refuses what does not fit, and a witness measures how late each wake was. That is the floor a robot's brain or a controller stands on.

"Real time" is two promises. The first: a loop runs when it should nearly always, and you can measure how nearly — a Linux kernel built to be interrupted almost anywhere, with fine timers, keeps that on a PC or a Raspberry Pi. The second: a loop runs when it should every time, by construction — which no Linux can promise and a microcontroller running one compiled loop can. A robot needs both, the first in the brain that plans and the second in the body that moves. Harobanda takes the first here; the second belongs to its edge profile, on the MicroRing substrate of the same project, and is not built.

Can a real-time operating system be built on it? Yes — that is what the floor is for. The kernel's own deadline scheduler, which most systems never use, is what a declared program gets: a reservation held on a core set apart, with nothing to configure and no priority to pick. The loop stays the program's own, as it would in any real-time system; what the machine adds beneath it is time the kernel holds and a number you can read.

What a program is given

Three things, each read back from the kernel.

A timed kernel

A machine that reserves time for any program is built a kernel that can be interrupted almost anywhere, with timers that resolve to the nanosecond — derived from the declaration, never asked for by name. At every boot the machine reads back what it got, and one handed a calm kernel differs from its expectation before any program runs.

A reservation

A program declares its period, its deadline, its runtime and its core: 200 microseconds of every 1000, done within 500, on core 1. The kernel's own deadline scheduler holds it there, on a core set apart for reserved programs, and refuses a set that does not fit. The program never sets its own place in the queue; it is given one before it starts.

A measurement

A witness runs the declared period on an absolute timer and says how late each wake was: the median, the 99th, the worst, and how many periods ran past the deadline. In an emulator those numbers are the laptop's, so the kept transcript holds the line's shape and none of its numbers.

What the machines said

Every line is quoted from a pinned boot.

a timed machine, from its pins
# the kernel, read back before any program runs
boot: timed -- the kernel is PREEMPT_RT and its timers resolve 1 ns, as it says of itself
boot: reserve -- control 200 us of every 1000 us, within 500 us, on core 1, second 700 us of every 1000 us, within 1000 us, on core 1; the kernel holds each reservation and refuses what does not fit

# two programs ask the kernel what they run under, from inside
reserved: SCHED_DEADLINE -- 200 us of every 1000 us, within 500 us, on core 1 and no other: as the kernel reports it, and what this world spawns runs unreserved
reserved: no reservation -- this world runs under policy 0 on 1 core, and gets what is left

# the witness, beside a program that burns the same core
tick: 1000 periods of 1000 us, deadline 500 us -- under SCHED_DEADLINE (200 us of every 1000 us), on core 1 and no other
tick: measured -- woke late by N us at the median, N us at the 99th, N us at the worst; the step took N us at the worst; N of 1000 past the deadline

A pinned boot is a transcript the repository keeps and compares, line for line, with each new run. The first line is the kernel's own word about itself. The reserved program has core 1 and no other; the one with no reservation has the one other core. Every N in the witness's line is a number on the screen and the letter N in the pin — on the laptop these pages were written on, about 400 microseconds late at the median and 20 milliseconds at the worst: the emulator's number, not the machine's. A board gives the first that counts.

Who it is for

The floor of a robot, and of anything that answers a sensor on time.

Harobanda is the floor of a real-time solution: it gives the control loop its time and proves it, and leaves the loop to the program that owns it. The loop is written in the Haro language, which owes it bounded execution; the robot is designed in Softanza's own design language, which says what the body is and what a safe state is; and whatever intelligence sits above them stays outside the deadline path, proposing to a layer that decides. What exists today is the floor's part, run in an emulator; the rest is on the last page of this section.
