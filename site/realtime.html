Real time

A machine that gives a program its time.

A control loop that must run every millisecond needs more than a fast computer. It needs time that nothing else on the box can take, and a way to know how late it was. Here a program declares the time it needs, the kernel keeps it and refuses what does not fit, and a witness measures it. Three of the six steps are built; every boot on these pages ran in an emulator, and the number that counts is a board's.

Two promises

Firm on the box, hard at the edge.

"Real time" is two promises that are usually confused. The first is that a loop runs when it should nearly always, and that you can measure how nearly: a Linux kernel built to be interrupted almost anywhere, with fine timers, can keep that on a PC or a Raspberry Pi, and a measurement says what "nearly" was. The second is that a loop runs when it should every time, by construction, which no Linux can promise and a small microcontroller running one compiled loop can. A robot needs both: the first in the brain that plans, the second in the body that moves.

Harobanda takes the first promise here, on the machines it already boots. The second belongs to its edge profile, where a program is compiled onto a microcontroller by the MicroRing substrate of the same project, and is not built. One declaration will one day name both, the brain and the body, and the wire between them; that is the last of the six steps.

It is not a real-time operating system, and it does not try to be one. A program here has no priorities to set and no scheduler to call: the loop is still the scheduler. What the machine adds is a reservation the kernel keeps, and a number you can read.

What a program is given

Three things, each read back from the kernel.

A timed kernel

A machine that reserves time for any program is built a kernel that can be interrupted almost anywhere, with timers that resolve to the nanosecond. It is derived from the declaration, never asked for by name, and at every boot the machine reads back what it got: a machine handed a calm kernel differs from its expectation before any program runs.

A reservation

A program declares its period, its deadline, its runtime and the core it runs on: 200 microseconds of every 1000, done within 500, on core 1. The kernel's own deadline scheduler holds it there, on a core set apart for reserved programs, and refuses a set that does not fit. The program never sets its own place in the queue; it is given one before it starts.

A measurement

A witness runs the declared period on an absolute timer and says how late each wake was: the median, the 99th, the worst, and how many periods ran past the deadline. In an emulator those numbers are the laptop's, so the kept transcript holds the line's shape and none of its numbers. A board gives the first number that counts.

What the machines said

Every line is quoted from a pinned boot.

A pinned boot is a transcript the repository keeps and compares, line for line, with each new run: if a machine says something else, the comparison fails. These lines are from two machines, one that gives two programs their time and one that measures it.

a timed machine, from its pins
# the kernel, read back before any program runs
boot: timed -- the kernel is PREEMPT_RT and its timers resolve 1 ns, as it says of itself
boot: reserve -- control 200 us of every 1000 us, within 500 us, on core 1, second 700 us of every 1000 us, within 1000 us, on core 1; the kernel holds each reservation and refuses what does not fit

# two programs ask the kernel what they run under, from inside
reserved: SCHED_DEADLINE -- 200 us of every 1000 us, within 500 us, on core 1 and no other: as the kernel reports it, and what this world spawns runs unreserved
reserved: no reservation -- this world runs under policy 0 on 1 core, and gets what is left

# the witness, beside a program that burns the same core
tick: 1000 periods of 1000 us, deadline 500 us -- under SCHED_DEADLINE (200 us of every 1000 us), on core 1 and no other
tick: measured -- woke late by N us at the median, N us at the 99th, N us at the worst; the step took N us at the worst; N of 1000 past the deadline

The first line is the kernel's own word about itself: the machine reads back what it got rather than repeating what it asked for, and that line said 4 ms twice before it said 1 ns. The second names both reservations before any program runs. Then two programs ask from inside: the reserved one has core 1 and no other, and the one with no reservation has the one other core, because a reserved core is set apart. The last two lines are the witness, and every N is a number on the screen and the letter N in the pin: on the laptop these pages were written on, about 400 microseconds late at the median and 20 milliseconds at the worst. That is the emulator's number, not the machine's.

Who it is for

The floor of a robot, and of anything that moves.

The direction is autonomous machines: a robot, a vehicle, a line in a plant, a device that answers a sensor on time. Harobanda is the floor of that. It gives the control loop its time and measures it, and it refuses to be more. The loop's program is written in the Haro language, which owes it bounded execution; the robot is designed in Softanza's own design language, which says what the body is and what a safe state is; and whatever intelligence sits above them stays outside the deadline path by construction, proposing to a layer that decides.

None of that has moved a motor yet. What exists is the floor's part, run in an emulator, and the honest list is on the last page of this section.
